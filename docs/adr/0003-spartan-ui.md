# ADR 0003: spartan/ui as the design foundation

## Status

Accepted. Supersedes [ADR 0002](0002-design-foundations.md).

## Context

ADR 0002 established a hand-rolled semantic token layer over Tailwind v4
(`surface`/`ink`/`accent`/state colors) with a "flag, don't decide" rule for
extracting repeated utility clusters into primitives under `src/app/ui/`. Two
tickets later the weakness of that approach was visible: the same button
cluster appeared 6+ times and the same input cluster 5 times across four
templates, and no extraction had happened — the rule deferred every decision
to the owner, so primitives never materialized.

The owner decided to adopt [spartan/ui](https://spartan.ng) as the design
foundation instead of maintaining a bespoke token layer, and to use its
AI-facing tooling (MCP server, agent skill) as the supported way for agents
to work with the library.

Alternatives considered:

- **Keep the ADR 0002 tokens, extract primitives as planned** — rejected:
  the extraction rule wasn't producing primitives, and a hand-rolled
  component set re-solves accessibility (focus, keyboard, ARIA) that spartan
  brain already provides.
- **Angular Material** — rejected for the same reasons as in ADR 0002, and
  it doesn't compose with the Tailwind workflow the owner uses daily.

## Decision

- **spartan/ui is the design foundation.** Brain (`@spartan-ng/brain`,
  headless accessible primitives, npm dependency) + helm (`@spartan-ng/helm`,
  styled components copied into `web/libs/ui/` — owned and editable).
  Components are added per-component with `ng g @spartan-ng/cli:ui <name>`.
- **Theme**: spartan's default (Neutral palette, default radius). Theme
  values are CSS variables in `web/src/styles.css`, generated by
  `ng g @spartan-ng/cli:init --theme neutral`; change values there or via
  the spartan theming docs, not by inventing parallel tokens.
- **The ADR 0002 token layer is deleted.** Templates use spartan's semantic
  utilities (`bg-primary`, `text-muted-foreground`, `text-destructive`,
  `border-border`, …). The old `surface`/`ink`/`accent` vocabulary is gone.
- **Dark mode**: class-based (`.dark` on `<html>`, per spartan). A toggle in
  the app shell persists the choice in localStorage and defaults to the
  system preference. This replaces ADR 0002's `prefers-color-scheme`-only
  approach and pre-empts the deferred "settings toggle" decision.
- **Forms stay on Signal Forms.** Helm's CVA-oriented field components are
  not adopted; forms compose helm's styling-level primitives (`hlmInput`,
  `hlmLabel`, `hlmBtn`) with `[formField]`.
- **Domain state colors** (due-ok, due-soon, overdue, pending-sync from ADR
  0002) are not carried over yet — no current screen uses them. When ticket
  08 (home screen) needs them, add them as custom spartan variables
  (`--warning` etc. registered via `@theme inline`, per spartan's theming
  docs) in that ticket, not before.
- **AI tooling**: the `@spartan-ng/mcp` server is configured at repo root
  (`.mcp.json`) and the official spartan skill is installed at
  `.agents/skills/spartan` (tracked in `skills-lock.json`). Agents use these
  to confirm component APIs instead of guessing.
- **Touch target / iOS zoom rules from ADR 0002 still apply**: the 44px
  minimum is baked into the vendored helm defaults — `hlmBtn` default is
  `h-11` (icon size `size-11`, lg `h-12`) and `hlmInput` is `h-11`. These
  are marked local edits in `web/libs/ui/`; regenerating a component with
  the CLI reverts them, so re-apply after any regeneration. Form inputs stay
  at 16px+ (`hlmInput` is `text-base`).

## Consequences

- `docs/design.md` is rewritten to describe the spartan token vocabulary;
  `web/AGENTS.md`'s styling section now points at helm components instead of
  the extraction-proposal rule. The `src/app/ui/` primitive rule is retired
  — new primitives are spartan components, not hand-rolled extractions.
- `web/libs/ui/` is committed source (helm is copy-in, not a dependency);
  edits there are normal changes, but regenerating a component from the CLI
  overwrites them.
- `components.json` in `web/` is the spartan project config; its presence
  auto-activates the spartan skill for agents.
- Deleting the old token layer means any ticket written against ADR 0002
  vocabulary (e.g. "state colors") must be read through this ADR instead.
